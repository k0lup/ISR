## Запуск и завершение

1. main() создаёт QApplication, регистрирует метатипы для сигналов, настраивает стиль и запускает логгер. Затем создаёт стековый Application. main.cpp
2. Application читает два обязательных позиционных аргумента .cfg и .on и необязательный путь .on_s284. При ошибке показывает критическое сообщение. main() входит в основной цикл событий только при успешной инициализации. Аргументы · Проверка старта
3. При успешной инициализации Application создаёт окно и сервисы, переносит исполнитель в отдельный QThread, связывает компоненты, показывает окно и планирует начальную загрузку списка разделов через singleShot(0, ...). Инициализация
4. После возврата из основного цикла main() останавливает логгер. Затем уничтожается стековый Application. Его деструктор запрашивает quit() и ждёт рабочий поток. Сигнал QThread::finished связан с deleteLater() исполнителя. Выход из main · Деструктор

## Потоки и взаимодействия

| Путь | Что передаётся и где выполняется |
|---|---|
| Запуск → SectionsLoader | Начальное чтение списочных .SET происходит в главном потоке. singleShot откладывает начало чтения до цикла событий. Сами чтение и разбор синхронны. Вызов · Чтение |
| GUI → загрузчик → исполнитель | Загрузчик принимает имя раздела, запрашивает у исполнителя статус, читает .SET и .DII и передаёт SectionStruct. DiiReader работает в потоке загрузчика. Связи загрузчика · Загрузка раздела |
| GUI ↔ исполнитель | Запуск директивы, переключение режима, отмена варианта и ответы диалогов идут к исполнителю. Снимки исполнения, запросы диалогов и сообщения идут обратно. Qt доставляет межпоточные сигналы через очереди. Соединения |
| Исполнитель ↔ запросы | Для диалогов, ПРИС и загрузки исполнитель связывает RequestId с QPointer<Direct>. Внутренние запросы загрузчика используют отдельные ID и карты имён разделов. Связь ID с директивой · Карты загрузчика |
| Исполнитель → ПРИС | В активном пути Application принимает PRISMessage, игнорирует его содержимое и ставит в очередь ответ со status = true и исходным ID. Подключение внешнего Server по этому пути не реализовано. Имитация ПРИС · Документированный обмен (REQUIREMENTS.md#источники) |

## Состояния и владение

- MainWindow различает стадии инициализации, выбора, подготовки, загрузки и ошибки. Таблица enabledMap управляет доступностью действий. ProgramViewWidget создаётся с родителем MainWindow и содержит модель таблицы. Состояния GUI · Владение GUI · Модель
- DirectiveExecutor различает Initialization, Idle, Runned, Failed. Режим STEP или AUTO хранится отдельно. Кадр раздела содержит активную главу, индексы, выбранные варианты, автоблоки и ссылку на вызывающую директиву. После успешной операции AUTO продолжает исполнение в границах блока. Загрузка вложенного раздела может добавить кадр. Путь снятия кадра с продолжением вызывающей директивы в обследованном коде не найден. Модель исполнения · Добавление кадра · Завершение директивы
- QThread имеет родителем Application. Исполнитель переносится в этот поток. Создаваемые Direct имеют исполнителя родителем. SettingsStore — поле Application, потребители работают со ссылками на него. Создание объектов · Поля Application · Родитель директив

## Открытые риски

| ID | Наблюдение и граница вывода |
|---|---|
| RISK-01 | Загрузчик хранит один current_load_request_id. Перекрытие запросов потенциально может изменить привязку результата. Допустимость такого перекрытия и сценарий уже загруженного вложенного раздела требуют проверки. Загрузчик |
| RISK-02 | snapshot() возвращает ссылку после освобождения блокировки, setAppCfg() пишет под QReadLocker. Стартовая запись происходит до запуска исполнителя. Возможная конкурентная мутация требует отдельного разбора. SettingsStore · Порядок старта |
| RISK-03 | Окно, загрузчик и каталог получают deleteLater() из деструктора после выхода из основного цикла. MainWindow::destroyed связан с deleteLater() стекового Application. Порядок доставки событий уничтожения и последствия требуют проверки. Завершение |

ID соответствуют записям бэклога. Сбои по этим сценариям при онбординге не наблюдались.
