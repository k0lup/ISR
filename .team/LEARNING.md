# Журнал обучения проекта
Записи: дата, ID задачи, навык, собственная гипотеза, уровень помощи (1–6), замечания ревью, что понял, что проверил самостоятельно, следующий шаг.
Не переносить служебные сведения в личный профиль. Ментор предлагает обобщённые выводы; человек проверяет их перед переносом.

## 2026-11-27 — встреча с системным аналитиком

- REQ-Q01. Обсуждали, как подтвердить готовность релиза. Разработчик описал, что несколько человек проверят обычные способы работы, а сам он постарается проверить все возможности. Он отдельно отметил, что этот план не гарантирует полноты проверки.

## 2026-11-27 — встреча с тимлидом

- Выбор следующей задачи. Разработчик соотносит сложность задачи с доступными силами. Когда сил меньше, предпочитает понятную и хорошо описанную задачу. Обычно сначала берётся за более простые задачи.
- Разработчик назвал две ключевые для него темы. По отображению разделов предложил рабочую идею и выразил сомнение в ней. По сетевому обмену отметил, что пока сложно разобраться. [WIP-04 и WIP-01](BACKLOG.md#незавершённая-функциональность)
- Разработчик начал разбирать обмен Windows-версии с ПРИС на обычном сеансе от запуска до сохранения протокола. Он предложил сверять увиденное с документацией и связал ожидаемую сложность проектирования с форматом запросов и ответов. Результаты разбора отдельных сообщений на встрече не обсуждались.

## 2026-11-27 — встреча с архитектором

- WIP-04. Разработчик объяснил на примерах, как Windows-версия сохраняет число пустых строк между директивами. Для Astra выбрал добавлять недостающий разделитель и обосновал это читаемостью таблицы.
- WIP-04. Разработчик указал, где в существующих данных искать границы блока НШС, и предложил использовать первую и последнюю директивы для размещения меток. Чтение кода подтвердило, что имя блока и индексы его директив уже доступны интерфейсу в `ExecutionSnapshot`.
- WIP-04. Для строки с меткой разработчик предложил использовать имеющееся значение `NoDirectiveIndex`. Чтение кода подтвердило, что при отрицательном `directive_index` обработчик двойного щелчка завершается до запуска директивы.

## 2026-11-27 — встреча с техническим наставником

- REQ-Q02. При разборе обмена с ПРИС разработчику пока трудно связать структуру сообщений с полями «род», «сорт» и «тип». Обсудили, как порция и атомы связаны между собой и как искать сочетание этих полей в описании.
- REQ-Q02. Разработчик уточнил, что основной вопрос для него — где в программе формировать сообщение для отправки и где полученные байты превращать в результат, понятный исполнителю директив.
- REQ-Q02. В качестве первого примера результата для исполнителя разработчик назвал признак успешности операции и комментарий, если он есть. Он отдельно отметил, что с ПРИС обменивается сообщениями не только исполнитель.
- REQ-Q02. В качестве примеров обмена за пределами работы исполнителя разработчик назвал загрузку раздела из меню и сохранение протокола. Возможность получения списка каталогов от ПРИС он обозначил как вопрос. Обсудили, что перед проектированием можно описать один обмен словами: кто его начинает, что хочет сделать и кому нужен результат.

## 2026-11-27 — встреча со специалистом по ревью кода

- Перед завершением задачи разработчик оценивает, как устроено решение, и проверяет его работу вручную. По его словам, писать автоматические тесты он пока не умеет.
- Сомнение в устройстве правки разработчик пока описывает как ощущение, что временный обход может создать трудности позже.
- WIP-04. На примере таблицы разработчик назвал конкретный риск: вставка строк для оформления усложнит подготовку к показу. Он предложил явно хранить строки для показа в структуре раздела и предположил, что такое изменение затронет несколько сервисов.
- WIP-04. Разработчик различил добавление строк для оформления внутрь директивы и переделку всей структуры раздела. Для первого случая указал на зависимость проверки директив от их строк. Для второго отметил возможное влияние на исполнитель и интерфейс. Чтение кода подтвердило использование текущих данных этими частями программы.

## 2026-11-27 — встреча с ментором по профессиональному развитию

- WIP-04. Разработчик предложил вручную проверить два действия: нажатие на метку не запускает директиву, нажатие на строку директивы запускает выполнение. При неожиданном результате он предложил посмотреть журнал программы и при необходимости использовать отладчик Qt Creator. Это описание проверки, запуск на встрече не выполнялся.
- WIP-04. Чтобы узнать, какая директива запустилась, разработчик предложил сверять отправленное при запуске сообщение с ожидаемым сообщением из данных директивы.
- В обсуждениях разработчик обосновал выбор источника ожидаемого поведения, обозначил пределы ручной проверки и нашёл конкретные зависимости в задаче с таблицей. При обсуждении ПРИС он различил данные, которые передаются по сети, и результат, нужный исполнителю. Сведения об автотестах получены из самоописания. Работу с Git и результаты запуска в этой серии встреч не проверяли.
- Ментор предложил два самостоятельных упражнения. Для WIP-04 описать ручную проверку метки и двух директив с разными сообщениями, чтобы отличить правильный запуск от запуска соседней директивы. Для REQ-Q02 отдельно описать, какие данные передаются при одном обмене и какой результат нужен части программы, которая его ждёт. Упражнения предложены, результаты ещё не получены.
